# 0429 PID New 检查报告

## 结论

本轮检查对象是当前项目中的 `PID new` view，核心实现位于 `src/core/contourPid.ts` 和 `src/views/PidNewView.vue`。对照参考仓库 [Probabilistic-Inclusion-Depth](https://github.com/cenyangWu/Probabilistic-Inclusion-Depth) 的 README 与 `PID/Boxplot.py` 后，结论如下：

1. **PID new 基本符合参考仓库的 PID-Mean 原理**。当前实现将每个 layer 转换为 time-value fuzzy mask，计算 mean mask，再用双向 inclusion 的两个归一化分数取最小值作为 depth。这与参考仓库中 PID-Mean 的核心公式一致。
2. **PID new 不是完整 pairwise PID**。参考仓库完整 PID 会对 ensemble 中每对 mask 计算 probabilistic inclusion，并分别聚合 `IN_in` 与 `IN_out`；当前实现使用 mean mask 近似，因此应称为 `PID-Mean` 或 `PID-Mean adaptation`，不应称为完整 PID 复现。
3. **contour boxplot 的主要结构基本正确**。当前绘制了 all-member union、central 50% union、central 50% intersection、deepest member，符合参考实现生成 contour boxplot 的主要组成元素。
4. **当前 contour boxplot 是项目数据的 time-value fuzzy mask 适配版**。参考仓库主要处理 2D/3D binary 或 fuzzy contour mask；本项目先把 time-series uncertainty band 栅格化到 `(time, log1p(value))` 空间，因此属于合理适配，而不是原始医学/标量场 contour 数据的直接复刻。
5. **存在几个需要在论文或说明中声明的小差异**：ROI 只影响显示窗口，不影响 PID new depth 计算；`valueTransform` option 当前类型上存在但实际固定为 `log1p`；未做参考 `Boxplot.py` 中的 largest connected component 过滤。

## 1. 参考方法核对

参考仓库 README 定义的 probabilistic inclusion operator 是：

```text
u subset_p v = integral(u * v) / integral(u)
```

完整 PID 对每个 contour member `u_i` 计算：

```text
IN_in(u_i)  = average_j (u_i subset_p u_j)
IN_out(u_i) = average_j (u_j subset_p u_i)
PID(u_i)    = min(IN_in(u_i), IN_out(u_i))
```

参考仓库同时给出高效版本 PID-Mean：

```text
meanMask = average_i u_i
IN_in_mean(u_i)  = integral(u_i * meanMask) / integral(u_i)
IN_out_mean(u_i) = integral(u_i * meanMask) / integral(meanMask)
PID-Mean(u_i)    = min(IN_in_mean(u_i), IN_out_mean(u_i))
```

`PID/Boxplot.py` 中的实现也对应这个形式：

```python
dot_product = np.sum(masks_flattened * original_center, axis=1)
s1 = dot_product / area_masks
s2 = dot_product / area_center
depths = np.minimum(s1, s2)
```

因此，判断当前项目是否“符合 PID 基本原理”时，需要区分完整 pairwise PID 与 PID-Mean。当前项目符合 PID-Mean，不是完整 pairwise PID。

## 2. PID new 算法核对

当前 `PID new` 的入口是 `computeContourPid(...)`，见 `src/core/contourPid.ts`。

### 2.1 mask 构造

当前实现先对每个 `LayerInput` 构造五条 band series：

- `lowOuter`
- `lowInner`
- `center`
- `highInner`
- `highOuter`

来源优先级大致是：

- outer band：`p025/p975`、`p05/p95`、`p10/p90`、`lower/upper`、`mean +/- unc/2`
- inner band：`p25/p75`
- center：`p50` 或 `mean`

随后 `rasterizeBand(...)` 把每个 layer 栅格化到二维空间：

```text
x = time index
y = log1p(value)
u_i(t, y) in [0, 1]
```

membership 是 trapezoid fuzzy band：

- outer band 外部为 `0`
- inner band 到中心附近为 `1`
- outer 到 inner 之间线性过渡

这个设计把 time-series uncertainty band 转换成 fuzzy contour mask。它不是参考仓库原始数据类型，但符合 PID 对 mask/probability field 的输入要求。

### 2.2 depth 计算

当前实现的关键代码逻辑是：

```text
meanMask = average(masks)
areaMean = sum(meanMask)
area = sum(mask)
dot = dot(mask, meanMask)
inScore = dot / area
outScore = dot / areaMean
depth = min(inScore, outScore)
```

这正好对应 PID-Mean：

```text
u_i subset_p meanMask
meanMask subset_p u_i
min(two directions)
```

因此，`PID new` 比旧的 `computePidOrdering(...)` 更接近参考仓库的基本原理。

### 2.3 与旧 PID ordering 的区别

旧 PID ordering 位于 `src/core/pidOrdering.ts`。它的主要逻辑是：

```text
检查 layer i 的 center(t) 是否落入其他 layer j 的 uncertainty interval
再对时间求平均
```

并且旧方法有 width penalty：

```text
weight = 1 / (1 + widthRatio)^p
```

所以旧方法更准确的名称应是：

```text
PID-inspired weighted interval inclusion depth
```

旧方法不是参考仓库的 mask-based PID，也不能直接生成 contour boxplot。`PID new` 则已经转向 mask-based PID-Mean。

## 3. contour boxplot 绘制核对

当前 contour boxplot 绘制位于 `src/views/PidNewView.vue` 的 `drawContourPanel(...)`。

### 3.1 当前绘制的元素

当前 view 绘制了四类 mask：

| 元素 | 当前实现 | 参考方法中的对应意义 | 判断 |
|---|---|---|---|
| all union | `allUnionMask` | 所有 ensemble members 的外包络 | 基本正确 |
| central 50% union | `centralUnionMask` | depth 前 50% members 的 union | 基本正确 |
| central 50% intersection | `centralIntersectionMask` | depth 前 50% members 的 intersection | 基本正确 |
| deepest member | `deepestMask` | depth 最大的单个 member | 基本正确 |

这些元素与参考 `PID/Boxplot.py` 中生成的 top-50% depth union、all masks union、top-50% depth intersection、deepest member 一致。

### 3.2 contour 提取方式

当前实现使用 `d3.contours()` 从 mask array 中提取等值线：

```text
threshold = contourThreshold = 0.5
```

这等价于对 fuzzy mask 使用 0.5 isocontour。参考仓库在 mask operation 前也使用 `>= 0.5` 对 mask 进行二值化，因此阈值选择在原则上是合理的。

### 3.3 差异与风险

当前绘制仍有三点需要说明：

1. **没有 largest connected component 过滤**  
   参考 `PID/Boxplot.py` 在保存 union/intersection/deepest 结果前，会调用 connected-component labeling 并保留最大连通分量。当前 `d3.contours()` 会画出所有满足阈值的 contour polygon，可能保留小碎片。

2. **central 50% 数量使用 floor**  
   当前实现为：

   ```text
   centralCount = floor(N * centralFraction)
   ```

   参考实现也使用 `total_count // 2`。这点一致。若 N 为奇数，则 central region 使用较小的一半成员。

3. **union/intersection 在 fuzzy mask 上先聚合再取 contour**  
   当前 `allUnionMask`、`centralUnionMask` 使用逐点 `max`，`centralIntersectionMask` 使用逐点 `min`，最后通过 0.5 threshold 绘制。参考实现则先二值化再做 boolean union/intersection。对于 fuzzy mask，两者不一定完全等价，但当前方式是 fuzzy-set 语义下合理的 union/intersection。

## 4. ROI 与显示排序

`PidNewView.vue` 中，ROI 通过 `activeIndices` 控制 x 轴显示和 river/contour 的可见时间范围，但 `computeContourPid(dataset.layers, ...)` 使用的是完整 `dataset.layers`，没有裁剪到 ROI。

因此：

- 当前 PID new depth 是 full timeline depth。
- ROI 只影响视图展示范围，不影响 PID new rank。
- 如果论文或实验声称“ROI 内 PID new depth”，当前实现不支持这个说法；应改为“full timeline PID new depth shown within the selected ROI window”。

排序方面，当前 `depthOrder` 按 PID-Mean depth 降序排列，然后通过 `buildPidCenterOutOrder(...)` 转换为 center-out river display order。也就是说：

- depth rank 表示统计中心性。
- river 中的上下位置不是直接 rank。
- 越靠近 stream 中心越表示 depth 越高，边缘表示 depth 较低。

## 5. 小问题与建议

1. **命名建议**  
   推荐在 UI、论文、报告中称当前方法为：

   ```text
   PID-Mean over time-value fuzzy masks
   ```

   或：

   ```text
   time-value fuzzy-mask adaptation of PID-Mean
   ```

   避免直接写成“完整实现 Probabilistic Inclusion Depth”。

2. **`valueTransform` option 当前未真正可配置**  
   `ContourPidOptions` 暴露了 `valueTransform?: "log1p"`，但实现中 `transformValue(...)` 固定使用 `Math.log1p(...)`。这不是算法错误，但说明 option 目前只是文档式占位，不是可扩展接口。

3. **ROI 语义需要写清楚**  
   如果后续需要 ROI-local PID，需要在 `computeContourPid` 前裁剪每个 layer 的时间序列，或者给 `computeContourPid` 增加 time index/window 参数。

4. **可选增加 connected-component 过滤**  
   如果希望更接近参考 `Boxplot.py` 的 contour boxplot 输出，可以在 contour mask threshold 后只保留最大连通区域。不过对 time-value stream data 来说，小碎片有时可能表达真实的间断 uncertainty region，因此是否过滤需要根据论文叙事决定。

5. **建议补充测试**  
   可添加一个小型 synthetic mask 测试，验证：

   ```text
   depth = min(dot(mask, meanMask) / area(mask),
               dot(mask, meanMask) / area(meanMask))
   ```

   并验证 deepest、central union、central intersection 的成员选择与 depth rank 一致。

## 6. 总体判断

当前 `PID new` 的算法与 contour boxplot 绘制可以认为是**基本正确的 PID-Mean 适配实现**：

- PID depth 公式与参考仓库 PID-Mean 一致。
- contour boxplot 的四个核心组件齐全。
- time-value fuzzy mask 是合理的数据适配。

但它不应被描述为完整 pairwise PID，也不应被描述为参考仓库医学/标量场 contour boxplot 的逐行复刻。更准确的表述是：

> We use a PID-Mean adaptation over time-value fuzzy masks for uncertainty-band streamgraph ordering and contour-boxplot visualization.
