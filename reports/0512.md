# 0512 Multiscale Baseline Review and Fix Report

Date: 2026-05-12

## Previous Reviewer Answer

As a Vis reviewer, the current pre-fix multiscale baseline was not a convincing
optimizer. It redistributed a local uncertainty-aware baseline shift over
Haar-like temporal bands, but it did not optimize a readability objective.

Truth assessment of the three statements:

1. "Original SineStream baseline optimization makes the centerline have one
   burst" is conditionally true. In the project Covid case, SineStream produced
   a dominant baseline derivative burst around 2022-01-15.
2. "The multiscale method uses different scales at each time stage and flattens
   the curve by introducing small waves in other time steps" was only partially
   true for the old implementation. It did spread local shifts across temporal
   bands, but the previous code forced the full local shift budget back into the
   baseline and treated `energyThreshold` mostly as diagnostics rather than as
   actual scale selection.
3. "This will optimize overall slope" was false for the old implementation.
   The earlier method could smooth a local burst-like derivative while making
   mean slope worse. Therefore the paper claim should not say "optimizes
   overall slope" unless the algorithm explicitly optimizes slope and enforces
   a global non-regression guardrail.

Recommended fix: make multiscale an actual optimizer by selecting temporal
scales with `energyThreshold`, optimizing scale coefficients against
`meanSlope`, `maxSlope`, curvature, and burst metrics, allowing the shift budget
to shrink, adding a burst metric, and requiring global `meanSlope`
non-regression.

## Implemented Fix

Core implementation:

- `src/core/baseline.ts`
  - Replaced forced full-budget redistribution with a coefficient optimizer.
  - `energyThreshold` now selects candidate Haar bands. If the threshold removes
    all bands, the strongest band is the only fallback candidate.
  - Optimizes signed scale coefficients using coordinate search.
  - Objective includes global center `meanSlope`, global `maxSlope`, curvature,
    max baseline derivative, baseline derivative concentration, and a small
    budget penalty.
  - Starts from zero shift, so the budget can shrink to zero.
  - Rejects any candidate that regresses global `meanSlope`.
  - Diagnostics now report selected scales, active coefficients, objective
    before/after, burst metrics, and guardrail status.

- `src/layout/metrics.ts`
  - Added `Max baseline derivative`.
  - Added `Baseline derivative concentration`.

- `src/core/optimizingUtils.ts`, `src/state/appState.ts`,
  `src/views/OptimizingVariantControls.vue`, `src/WorkbenchPage.vue`
  - Added independent `multiscaleEnergyThreshold` state/config for Current and
    Compare.
  - Exposed `energyThreshold` in the multiscale baseline controls.

- `src/app/sceneBuilder.ts`, `src/views/MetricsView.vue`
  - Surfaced multiscale optimizer diagnostics in notes and metric summaries.

## Case 1: Project Dataset

Dataset: Covid H1 in this project.

Window:

- Main stream: 2021-08-26 to 2022-04-15
- ROI: 2021-12-11 to 2022-03-12
- Ordering/baseline: TPID + multiscale, default `alpha=0.80`,
  `baselineUncertaintyWeight=0.45`, `energyThreshold=0.08`

Result: the optimizer selected 4 candidate scales but activated no coefficient.
This is an intentional guardrail result, not a fallback. It means the available
multiscale shift basis did not improve the combined objective without violating
the global mean-slope guardrail.

| Metric | SineStream | Optimized multiscale | Improvement |
|---|---:|---:|---:|
| ROI meanSlope | 115593.102 | 115593.102 | 0.000% |
| Global meanSlope | 21248.701 | 21248.701 | 0.000% |
| ROI maxSlope | 995979.670 | 995979.670 | 0.000% |
| Global maxSlope | 995979.670 | 995979.670 | 0.000% |
| ROI max baseline derivative | 1172798.170 | 1172798.170 | 0.000% |
| Global derivative concentration | 17.218 | 17.218 | 0.000% |

Diagnostics:

- SineStream top derivative: index 77, 2022-01-15, value 1172798.170
- Multiscale top derivative: index 77, 2022-01-15, value 1172798.170
- Selected scales: 8, 16, 256, 128
- Active coefficients: none
- Objective: 3.050 -> 3.050
- Global meanSlope guardrail: pass

Interpretation: this case confirms the reviewer concern. The project data has a
clear SineStream derivative burst, but the multiscale basis should not be
claimed to improve overall slope here. The fixed optimizer now refuses a harmful
or unsupported modification instead of redistributing shift just because a local
uncertainty signal exists.

## Case 2: Simulated Narrow Burst

Dataset: synthetic 8-layer stream with one narrow uncertainty-heavy burst around
time index 82 and a smaller shoulder around index 108.

Settings:

- ROI: index 68 to 98
- Baseline anchor: SineStream
- Multiscale: `baselineUncertaintyWeight=0.65`, `energyThreshold=0.08`

Result: the optimizer selected 5 candidate scales and activated only scale 16
with coefficient 0.10. The shift budget shrank from a local candidate budget of
66.572 to an applied budget of 0.287.

| Metric | SineStream | Optimized multiscale | Improvement |
|---|---:|---:|---:|
| ROI meanSlope | 0.827417 | 0.827373 | +0.0054% |
| Global meanSlope | 0.232706 | 0.232705 | +0.0002% |
| ROI maxSlope | 5.066159 | 5.065002 | +0.0228% |
| Global maxSlope | 5.066159 | 5.065002 | +0.0228% |
| ROI max baseline derivative | 5.070065 | 5.068908 | +0.0228% |
| Global derivative concentration | 13.022261 | 13.020172 | +0.0160% |
| ROI curvature proxy | 0.370748 | 0.370722 | +0.0069% |

Diagnostics:

- SineStream top derivative: index 80, value 5.070065
- Multiscale top derivative: index 80, value 5.068908
- Selected scales: 16, 128, 32, 64, 8
- Active coefficient: scale 16 -> 0.10
- Objective: 3.050000 -> 3.049777
- Global meanSlope guardrail: pass

Interpretation: the simulated case demonstrates the intended behavior. The
optimizer uses a small amount of multiscale correction, improves burst and slope
metrics slightly, and avoids full redistribution. The improvement is deliberately
small because the guardrail and budget penalty prevent the method from inventing
large compensating waves.

## Final Reviewer Position

After the fix, the correct claim is:

"The multiscale baseline variant performs constrained scale-coefficient
optimization over uncertainty-derived temporal bands. It accepts a correction
only when the combined slope, curvature, and burst objective improves while
global meanSlope does not regress."

The claim should not be:

"Multiscale always flattens the SineStream burst" or "multiscale always optimizes
overall slope."

The project Covid case is now an important negative result: it says the current
basis cannot safely improve that default view. The simulated burst case is a
positive sanity case: it verifies that the optimizer can select a small
multiscale correction when the data actually supports one.

## Addendum: Revised Research Formulation

The later formulation supersedes the hard global `meanSlope` non-regression
guardrail above. In the revised model, multiscale no longer uses uncertainty as
its scale signal. Uncertainty is treated as already semanticized by TPID layer
ordering. The multiscale baseline now derives temporal bands from layer
thickness slope variation.

The revised objective intentionally challenges the classic Stacked Graphs
geometry/aesthetics preference for minimizing global slope. It is not trying to
make the centerline flat. It tries to reduce derivative bursts and derivative
concentration while increasing centerline slope coverage, producing a bounded
small-wave centerline instead of a single raised burst.

Implementation status:

- `src/core/baseline.ts` now builds layer-slope Haar bands.
- Multiscale basis functions redistribute SineStream centerline derivative
  bursts into zero-endpoint wave shifts.
- The optimizer rewards centerline slope coverage and penalizes peak derivative,
  derivative concentration, curvature, excessive slope growth, and shift budget.
- The UI label is now `waveStrength`; the internal state name is retained for
  compatibility.
